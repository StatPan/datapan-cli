# Source rights boundary

## What Apache-2.0 covers

The repository [LICENSE](../LICENSE) grants Apache-2.0 permissions only for
original Datapan-authored code, scripts, documentation, schemas, examples, and
other original CLI material. The [NOTICE](../NOTICE) records the same boundary
for redistributors.

The license does **not** grant rights in upstream datasets, API responses,
provider documentation, provider marks, credentials, browser sessions, or
other third-party material that is requested, referenced, cached, exported, or
reachable through the CLI.

## Provider terms remain controlling

Each provider's current terms, attribution requirements, access conditions,
and redistribution limits control use of that provider's material. The CLI may
produce commands, local cache files, exports, generated clients, or diagnostic
receipts that identify an upstream source. Those outputs are not an
upstream-data sublicense and must not be treated as permission to collect,
reuse, publish, or redistribute provider material.

Before a contribution adds a provider integration, fixture, sample, or
documentation excerpt, verify the applicable source terms. If they are absent,
stale, ambiguous, or inconsistent with the proposed use, stop and obtain or
record the applicable terms. Do not infer a redistribution right from public
accessibility, an API key, a Registry entry, or Apache-2.0.

## Maintainer and contributor rules

- Keep credentials, browser profiles, and access entitlements out of this
  repository and generated release assets.
- Do not relabel provider material as Apache-2.0 or include it in a release
  merely because the CLI code is Apache-2.0.
- Preserve required provider attribution and official references in the
  appropriate Registry or provider contract record.
- Treat changes to provider terms, attribution, source identity, or access
  conditions as a review trigger, not as a metadata-only cleanup.

This document is an operational boundary, not legal advice. It does not change
any provider's terms or grant permission on a provider's behalf.
